# Security

Gentle Starter is intended as a local development base. Before publishing a
derived repo, make sure it does not include secrets, credentials, or local
environment state.

## Files that should not be published

Do not commit:

```text
.env
env/
.pi/
.atl/
```

These paths may contain local configuration, databases, sessions, credentials,
or state generated by assisted-development tools.

## `.env` and `.env.example`

Use `.env.example` as the versioned template:

```bash
cp .env.example .env
```

Rules:

- `.env.example` must contain only safe values or placeholders.
- `.env` should stay local and not be versioned.
- Do not add real tokens, passwords, private keys, or external service
  credentials to versioned files.

## Local state in `env/`

The `env/` directory is used to persist local state mounted in the container,
for example:

```text
env/.pi/
env/.engram/
env/.gitconfig/
```

That content belongs to the developer's machine. It should not be published or
copied between projects without review.

## Docker-in-Docker and elevated permissions

The devcontainer uses Docker-in-Docker and elevated permissions:

```yaml
privileged: true
```

```json
"runArgs": ["--privileged"]
```

This can be useful for flows that need Docker inside the container, but it
increases the access level of the environment. Use it only on machines and
projects where that risk is acceptable.

If your project does not need Docker inside the devcontainer, consider removing:

- `ghcr.io/devcontainers/features/docker-in-docker:3`;
- `privileged: true` in `.devcontainer/docker-compose.yml`;
- `--privileged` in `.devcontainer/devcontainer.json`.

## Git and GitHub

The container may mount local Git configuration in:

```text
env/.gitconfig/
```

Before publishing, check that there are no credentials or tokens in:

```text
env/.gitconfig/config
env/.gitconfig/.git-credentials
```

If you use `gh auth login`, treat the generated tokens as local secrets.

## Engram and local memory

Engram can store persistent information from the work done. Check its local
database before sharing an environment or copying `env/`:

```text
env/.engram/
```

It may contain decisions, project context, prompts, summaries, or sensitive data
mentioned during development.

## Pre-publication checklist

```bash
# View changes and unversioned files
git status --short

# Search for common sensitive terms
git grep -n "TOKEN\|SECRET\|PASSWORD\|PRIVATE_KEY\|API_KEY" || true

# Verify the base environment is still consistent
task doctor
```

Manually review any new files before committing, especially if they come from
`env/`, `.pi/`, `.atl/`, or local configurations.

## Reporting issues

If you find a security issue in this starter, open a private issue or contact
the repo maintainer before publishing sensitive details.
